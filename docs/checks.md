# 校验模型说明

[← 返回 README](../README.md)

点右侧「**运行校验**」会跑下面这些。**这些是本工具自己实现的近似模型**，目的是「不开游戏就能判断大致是否可行」，不是游戏内物理的精确复刻。

| 项目 | 说明 |
| --- | --- |
| **占地冲突** | 同一格被两个建筑占用；贴地图边缘的「不可建造区」 |
| **地形 / 山体** | 导入存档后按 `terrainAffordance` 检查蓝图：沼泽/软沙只有 `Light` 撑不住墙（`Heavy`）、水面要先铺桥、山体/矿石格要先开采 |
| **电力网络** | 照游戏 `PowerConnectionMaker` 的规则连网：**输电建筑（电缆/开关/发电机/电池）和 6 格内的用电器相连**，算出每张网的发电 · 耗电 · 储电与缺口 |
| **房间识别** | 自动 flood-fill 出封闭房间，显示面积、**空间评分**（拥挤/较紧/一般/…/极其宽敞，按游戏阈值）、门数量 |
| **通路可达性** | 从室外出发经门 BFS，找出「密封房间」「到不了室外」的区域 |
| **房间指定** | 房间用途（卧室/厨房/工坊/冷藏/冷冻…）要求的东西有没有；**温控**按目标温度算需要几台制冷机/加热器 |
| **制冷机冷热端** | 制冷机是「一冷一热」：两侧各是一个房间的话，一个变冷一个变热 —— 玩家最常见的翻车点 |

## 各项的实现细节

- **房间**：把「能封住房间」的建筑当作分界线做 flood-fill；与地图边界相连的区域算「室外」。
  分界线包括墙、栅栏、门，以及**嵌在墙里的制冷机 / 通风孔 / 蒸发制冷器** ——
  它们在游戏里不可通行，本身就是冷库密封的一环。
  注意床、桌子、工作台、发电机虽然也占格子（都带 `solid`），但**不算**分界线，否则一个房间会被切成一堆碎块。
- **空间评分**：`1.4 × 房间格数 − 0.9 × 被占格数`，再套用游戏的分档阈值。
- **电力**：把电力建筑占的格做正交相邻并查集，连通分量即一张电网，直接累加发电/耗电/储电。
- **温控**（近似模型，见 `js/rooms.js`）：
  ```
  冷（热）量需求 ∝ 面积 × |环境温度 − 目标温度|
  一台制冷机 ≈ 30 格 × 21°C 温差当量；一台加热器 ≈ 25 格 × 21°C
  需要台数 = ceil(面积 × ΔT / (每台的格数 × 21))
  ```
  在最常见的「常温 21°C → 0°C」下，等价于大家常用的「一台制冷机管 30 格」经验值。
  冷冻室（-10°C）比冷藏室（4°C）更费制冷机；**环境温度**可以在右侧「房间」面板里改。
- **房间指定**：用途写在房间的**每一格**上 —— 这样房间之后被拆开时两半都还保留这个用途（和游戏一致）。
- **地形 / 山体**：把存档里的 `<terrainGrid>` 和 `<compressedThingMapDeflate>` 解出来（raw deflate + base64，
  `uint16` 网格，值是 defName 的短哈希），再按 `TerrainAffordanceDef` 做 `Contains` 判断——
  和游戏 `GenConstruct.CanBuildOnTerrain` 同一套规则。**山体（自然岩石 ThingDef）会覆盖地形**，
  挡住建造，必须先开采；开采后地形变成 `X_RoughHewn`，仍然满足 `Heavy`。

> 想知道游戏里真正的规则，可以对照 `PowerConnectionMaker`、`Room`、`GenTemperature` 等类的实现。
> 本工具的校验结果只用于排查明显问题（漏了电缆、房间不封闭、冷库制冷不够），不要当成游戏内数值的保证。
